# Лабораторная работа № 2 — вариант 1

Параметры индивидуализации: N = 11, Q = 1, Y = 26.

V = 1 + ((17·11 + 7·1 + 26) mod 20) = 1.

Задача — рюкзак с двумя ограничениями: масса и объём. Представление — бинарная строка из 30 элементов. Функция цели — суммарная ценность выбранных предметов, которую нужно максимизировать.

## Основные файлы

`LR2_code.ipynb` содержит весь программный код.

`LR2.pdf` — отчёт с формулами, блок-схемой, таблицами, графиками и выводами.

`results/` содержит входные данные, параметры, полную серию результатов и графики. `figures/algorithm.png` — блок-схема для отчёта; она не является входным файлом программы.

## Установка и запуск

Распакуйте комплект в отдельную папку, чтобы не перезаписать `results/` другой лабораторной работы. Из этой папки выполните:

```bash
python -m pip install -r requirements.txt
jupyter notebook LR2_code.ipynb
```

В Jupyter выберите **Kernel → Restart Kernel and Run All Cells**. В VS Code достаточно открыть ноутбук и выполнить **Run All**. В Google Colab можно загрузить только `.ipynb`: дополнительные файлы для поиска не нужны, данные генерируются внутри ноутбука.

## Воспроизводимость

Seed данных — 261101, он вычисляется выбранным в работе правилом `10000*Y + 100*N + Q`. Одним генератором NumPy последовательно создаются 30 масс в диапазоне 1–30, 30 объёмов в диапазоне 1–20 и 30 ценностей в диапазоне 10–100 включительно. Лимиты — целая часть 35% суммы соответствующего ресурса: масса 184, объём 117. Формулы генерации данных являются выбором реализации, а не формулами назначения варианта из методички.

Seed экспериментов: 11001–11020. Набор предметов одинаков во всех запусках. Для каждого seed начальная допустимая популяция трёх конфигураций ГА совпадает. Реализация и примеры решений рассчитаны на данный экземпляр задачи; это не универсальный решатель всех 20 вариантов.

Параметры и версии Python, NumPy и pandas сохранены в `results/parameters.json`. Целочисленные ценности и выбранные наборы воспроизводятся в той же программной среде. Время работы зависит от компьютера и загрузки и не обязано совпадать.

## Эксперименты

|Метод|Обработка ограничений|Кроссовер|
|-|-|-|
|A|Ремонт|Одноточечный|
|B|Штраф|Одноточечный|
|C|Ремонт|Равномерный|
|RS|Тот же ремонт|Нет, независимые случайные строки|

A/B сравнивают обработку ограничений, A/C — вид кроссовера. В каждом случае проведено 20 запусков. Бюджет каждого запуска: 100 начальных особей + 300 поколений × 98 новых потомков = 29 500 оценённых решений. Повторяющиеся решения также считаются оценками; значения сохранённых элит не пересчитываются. Внутренние проверки ресурсов при ремонте не считаются отдельными оценками ценности, но входят во время работы.

RS не использует родителей и наследование. Поскольку после генерации применяется ремонт, распределение по допустимым решениям не является равномерным. Жадный ориентир рассчитывается отдельно и не относится к сравнению с равным бюджетом. Дополнительный контрольный повтор лучшего seed в последней ячейке не включён в основную серию из 80 запусков.

## Результаты и проверки

Средние ценности: A — 806,90; B — 804,90; C — 807,00; RS — 797,40. Лучший найденный набор имеет ценность 807, массу 179 и объём 117. Это не утверждение о доказанном глобальном оптимуме. Подробный анализ находится в отчёте.

`items.csv` содержит все 30 предметов; `examples.csv` — два допустимых и два недопустимых примера; `runs.csv` — 80 результатов с двоичными строками, ресурсами, долями допустимости, временем и бюджетом; `convergence.csv` — 301 контрольную точку каждого запуска; `summary.csv` — сводную статистику; `best_items.csv` и `best_solution.json` — лучший набор.

В поле `bits` сохраняются все 30 позиций. При самостоятельном чтении `runs.csv` задавайте для этого столбца строковый тип, чтобы сохранить ведущие нули.

Встроенные проверки контролируют бинарность, ограничения, ремонт, оба кроссовера, знаки штрафного фитнеса, пересчёт итоговых ценностей, бюджет и неубывание лучшей допустимой ценности. Последняя ячейка повторяет лучший запуск по seed и сравнивает набор и всю траекторию. Все ячейки предоставленного ноутбука выполнены без ошибок.
